# Project: Instant Replay + Trimmer (Windows-only)

## Non-goals (keep scope tight)
- No streaming, no cloud sync, no accounts.
- No timeline editor beyond simple IN/OUT trimming.
- No custom codec implementation (use FFmpeg).
- No cross-platform support (Windows only).

## Product goals
- Always-on background "Instant Replay" recording (keeps last X minutes).
- Hotkey saves last X minutes to a shareable MP4.
- Plain "record to file" mode as well as the replay buffer.
- Simple editor: open any video, preview, timeline scrub, IN/OUT trim, export presets.
- Light framing edits only: aspect crop, speed, volume. No layers, no text, no effects.
- Output size suitable for sharing (including a hard file-size target).

## Tech stack
- Electron + React + TypeScript
- Vite for renderer
- Electron Builder (preferred) for packaging
- FFmpeg as external process (bundled or downloaded on first run)
- Windows only (10/11)

## Architecture (hard requirement)
Electron is the UI shell only.
All capture/encoding/export is done via FFmpeg spawned from the main process.

### Processes
- Renderer (React): UI only, no direct filesystem or process access.
- Main (Electron): tray, hotkeys, settings, FFmpeg process management.
- Preload: typed, minimal IPC surface (contextBridge).

## Security & IPC rules
- `nodeIntegration: false` in renderer.
- All privileged actions go through preload `window.api`.
- IPC channels must be typed and namespaced:
  - `recorder:*`, `export:*`, `settings:*`, `app:*`
- Never expose raw `exec()` to the renderer.

## Recording design: rolling segments (must-do)
- Recorder writes small segments to `cache/` (default: 2 seconds per segment).
- Keep only last N minutes. Use segment wrap + an index file.
- Maintain an index (JSON) mapping:
  - segment filename
  - start timestamp (epoch ms)
  - duration seconds (expected 2)
- "Save Replay" selects segments whose timestamps cover last X minutes.
- Concatenate segments into `joined.mp4` using concat demuxer.
- Optional post-transcode for Discord-friendly size.

## Capture approach (Windows)
- Prefer FFmpeg desktop capture using `ddagrab` if available.
- If not available, fall back to `gdigrab` (slower but works).
- ddagrab produces D3D11 GPU frames. `h264_nvenc` accepts `d3d11` as an input
  format, so the cheapest path is **no video filter at all** — measured at
  1440p60 on a 3060 Ti: 0.08 s of CPU per 5 s captured, against 2.58 s once the
  frames round-trip through system memory and 11.05 s for software encoding.
  Any filter forces that round trip, so this path is off the moment scaling is
  requested. Prefer source resolution and resize on export.
  (`hwmap=derive_device=cuda` is *not* the way in: FFmpeg has no D3D11-to-CUDA
  device derivation, so that probe always fails and used to send every NVIDIA
  machine down the full CPU path.)
- Audio comes from DirectShow. Windows has no ffmpeg-native WASAPI loopback, so
  system audio needs Stereo Mix or a virtual cable; warn clearly when absent and
  keep recording rather than failing.
- Two sources (system + mic) are mixed with `amix` inside `-filter_complex`;
  `-vf` and `-filter_complex` cannot both drive the same stream.

## Capability detection (hard requirement)
`ffmpeg -encoders` reports what the binary was *compiled* with, not what will run.
Every encoder must be smoke-tested with a one-frame encode before being offered,
and the failure reason surfaced in Settings.

## The FFmpeg build is pinned — do not track "latest"
NVENC support is a compile-time contract: a build carries the NVIDIA Video Codec
SDK headers it was built against and refuses to run on an older driver. Tracking
the newest release silently raises the driver floor, and every machine below it
falls back to encoding on the CPU — which reads to the user as "recording makes
my games stutter", with working hardware sitting idle. `FfmpegManager` pins
7.1 (NVENC API 12.x, drivers back to ~551, GPUs back to Pascal).

**Pin to a permanently archived version tag, never a dated auto-build.**
BtbN's `autobuild-YYYY-MM-DD-HH-MM` releases are deleted within days — a URL
verified in the morning 404s by the afternoon, and the user meets it as a failed
download button. GyanD/codexffmpeg keeps its version tags indefinitely.

When changing the pin, verify NVENC still initialises on an older driver, and
remember the fix for an affected user is replacing the binary, never telling
them to update a driver they chose deliberately.

## Encoding rules (defaults)
- Container: MP4
- Video: H.264 (yuv420p / nv12), keyframes every ~2 seconds.
- Prefer constant-quality control:
  - NVENC: `-rc vbr -cq <value> -b:v 0` — `vbr_hq` no longer exists
  - x264: `-crf <value>`
- A preset ceiling is `-maxrate`/`-bufsize`, never `-b:v` (that is an average target).
- A hard file-size target switches to average bitrate computed from the *output* duration.
- Export presets (must exist):
  1) Small: 720p 30fps, higher compression
  2) Balanced: 1080p 60fps, medium compression
  3) High Quality: source resolution, larger output
- `-t` after `-i` caps the OUTPUT timeline, so it must be divided by the speed factor.
- `setpts` must come before `fps`, or the output frame rate is multiplied by speed.

## Stability requirements
- FFmpeg processes must be managed robustly:
  - log stderr to file
  - detect unexpected exit and expose status to UI
  - start/stop cleanly
- Prevent concurrent "Save Replay" operations (use a lock/queue).
- Cache cleanup must be safe (avoid deleting currently-used segments).

## UX requirements
- Tray app is the primary control surface.
- Hotkeys:
  - Save Replay: Ctrl+Shift+F10
  - Toggle Recording: Ctrl+Shift+F9
- UI pages:
  - Settings (replay length, fps, resolution, encoder, output path, audio toggles)
  - Editor (preview, IN/OUT, preset export, progress)

## Logging & diagnostics
- Write logs to `%APPDATA%/<AppName>/logs/`
- Include:
  - ffmpeg command lines used
  - encoder detection results
  - errors with stack traces
- Add a "Open Logs Folder" button in Settings.

## Build & test
- `npm run dev` / `npm run build` / `npm run package`
- `npm run typecheck` (node + web projects), `npm run lint`, `npm test` (vitest)
- `npm run icons` regenerates resources/icons from scripts/generate-icons.mjs
- The electron-vite config file MUST be named `electron.vite.config.ts` (dot, not
  dash) or it is silently ignored.

## Code quality rules
- TypeScript strict mode.
- No huge files; keep modules focused.
- Write helper functions for building FFmpeg args.
- Avoid magic numbers; store in defaults/presets.
- Prefer async/await; never block the main thread.
